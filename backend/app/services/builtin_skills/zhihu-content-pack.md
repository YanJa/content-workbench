# 知乎内容包

## 0. 先定形态

知乎一个平台上有三种完全不同的东西，篇幅差一个数量级。动手前先确认要哪一个；
用户没说就**默认回答**（它是知乎的主力形态，也是 SEO 长尾流量的来源）。

| 形态 | 篇幅 | 挂在哪 | 分发方式 |
|---|---|---|---|
| 回答 | 600-2000 字 | 某个问题下 | 搜索长尾，能躺几年 |
| 文章 | 1500-6000 字 | 自己的专栏 | 关注关系 + 首页推荐 |
| 想法 | 50-300 字 | 动态流 | 粉丝 + 话题 |

## 1. 回答体

```
第一句：结论（必须是能独立成立的判断句，不是"这是个好问题"）
        ↓
2-3 段：为什么这么判断，最有说服力的那个理由放最前
        ↓
分点展开：3-5 个 `##` 小标题，每点给一个具体支撑
        ↓
收尾：一句边界说明（什么条件下成立、什么情况下不成立）
```

- **前两屏决定生死**：知乎折叠长回答，读者不点「阅读全文」就等于你没写。结论必须在开头给完。
- 每点的支撑三选一：**数据**（给来源）/ **自己经历过的案例** / **读者照着能做的步骤**。纯说理在知乎等于没写。
- 拿不准就写明「这块我没有一手数据，以下是基于…的推断」。知乎认这个，不认嘴硬。

## 2. 专栏体

```
标题（15-30 字，陈述式或疑问式，不做标题党）
摘要（100 字内，列表页会露这段）
引言：为什么这个问题值得写（难在哪 / 常见解释错在哪）
4-6 节正文：提出 → 拆解 → 给方法 → 说边界（推进关系，不是并列堆料）
收尾：一到两句「读到这里能拿走什么」
```

- 至少给一处**可复现**的东西：一份清单、一组对比、一段操作步骤。
- 不升华、不呼吁、不写"让我们一起"。

## 3. 想法体

- 50-300 字，只讲**一个**观点或一件小事，不许展开成文章。
- 第一行就要有信息量：一个观察、一个反常识的判断、一个刚看到的数据。
- 口语短句，可以有"我 / 今天 / 刚发现"。
- 话题标签 1-3 个，单独最后一行。
- 不要写"你怎么看"——没人回就是没人回。

## 4. 增量自检（写回答时必做）

知乎回答最忌讳复述高赞已经说透的东西。动笔前先问自己：

1. 这个问题下的高赞回答，**已经把哪些角度说透了**？
2. 我手上有什么是它们没有的：更具体的操作步骤？更新的数据？反面案例？被忽略的前提？
3. 如果系统给了「同问题下的已有回答摘要」，**它们是边界不是素材** —— 避开它们说过
   的部分，严禁把已有观点复述成自己的结论。

交稿前再查一遍：删掉"希望对你有帮助""点赞收藏"，删掉"首先/其次/最后"，
删掉"作为AI"。这三样一出现，评论区就会替你回答。

## 5. 话题标签规范

- 回答、文章：**不需要**在正文里写标签，发布时在编辑器的「添加话题」里选（影响分发）。
- 想法：正文最后一行写 1-3 个，`#` 开头空格分隔。选**真有人在逛**的话题，不选生造词。
- 别堆无关大词，知乎会判不相关。

## 6. 格式纪律

- 中文全角标点；代码与英文专有名词保持原样。
- 正文不堆 emoji（知乎正文里 emoji 显得不专业），靠分段和加粗做层次。
- 关键判断用加粗，不要整段加粗。
- Markdown 输出即可，**不要写 HTML** —— 知乎有专门的渲染步骤，粘 Markdown 源码会原样显示符号。

## 7. 硬性事实

**知乎官方没有发布接口**。开放平台（developer.zhihu.com）提供的全是读能力：
热榜、搜索、问题推荐、问题回答摘要、创作数据。没有任何 create / publish / 草稿箱写入。

所以流程固定是：AI 生成 → 人确认 → 人复制到知乎编辑器 → 人发布 → 回来标记已发。
不要向用户承诺"帮你发到知乎"，也不要生成"已发布"之类的措辞。
