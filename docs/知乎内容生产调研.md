# 知乎内容生产：能力调研（2026-10-24）

调研问题：能不能在本系统里新增「知乎文案」的生产？知乎能发什么、系统能不能支持、
知乎有没有 API 或 Skill 能把内容同步过去。

---

## 0. 一句话结论

1. **不能自动发布**。知乎数据开放平台（`developer.zhihu.com`）是**只读**的，
   没有任何发布 / 写入 / 草稿箱接口。所以知乎**做不到**公众号那样的「推送草稿箱」，
   更做不到一键发布。
2. **能做、且很值得做**的是：把「知乎文案生产」做进系统——选题 → 成稿 →
   产出**可直接粘贴进知乎编辑器的富文本** → 深链跳转到知乎 → 人点发布；
   发布后把 URL 登记回来，**用官方接口回填阅读/赞同/评论数据**。
3. 官方提供的 MCP / Skill 是「让外部 AI 工具**读取**知乎数据」的三种接入方式，
   **不是**把内容写回知乎的通道。我们是自研 Agent 且已直连 REST，接 MCP 没有额外收益。

## 1. 知乎能发什么内容

| 形态 | 定位 | 建议篇幅 | 富媒体 | 本系统能否产出 | 判断 |
|---|---|---|---|---|---|
| **回答** | 挂在某个问题下，知乎 SEO 的主力载体 | 600–2000 字 | 图片、视频、引用 | ✅ 完全可以 | **ROI 最高**，先做它 |
| **文章（专栏）** | 系统长文、方法论与报告，长期沉淀 | 1500–6000 字 | 图片、表格/代码、引用 | ✅ 可以（复用公众号长文能力） | 第二优先 |
| **想法** | 轻量观点、速记、快讯 | 50–300 字 | 图片、短视频、链接 | ✅ 最容易产 | 顺带支持，成本极低 |
| 视频 | 演示 / 口播 | 1–10 分钟 | 视频、字幕、封面 | ⚠️ 部分（已有抖音口播稿与渲染管线，但规格不同） | 不建议现在做 |
| 提问 | 引导讨论 | — | — | ⚪ 运营价值低 | 不做 |
| 盐选 / 付费 | 订阅制内容 | 章节化 | 图片、图表 | ❌ 需官方合作资质 | 不碰 |

形态与篇幅口径参考第三方整理的[知乎内容形态矩阵](https://worktile.com/insights/gflur1avq5g4w7u63h8358uk)
（知乎官方未公布硬上限，取行业通行值）。

### 编辑器特性（决定我们的输出格式）

- 知乎编辑器是**富文本（ProseMirror）**：**粘贴 HTML 能保留格式；直接粘 Markdown
  源码不稳**。这条来自一手实践经验——[Zhihu Content Pack 技能包](https://ottermind.ai/zh-CN/skills/zhihu-content-pack)。
- Markdown 支持有限且文档含糊：标题 `#`~`####`、列表、链接、图片、代码块、引用、
  分割线、加粗/斜体可用，**不支持 LaTeX 公式**，图片尺寸控制受限
  （[知乎 Markdown 限制解析](https://tsight.io/articles/16787826)）。

> **对我们的直接影响**：现有公众号排版引擎产的是「内联 style、`<span leaf>` 包裹」
> 的公众号 HTML，粘进知乎会串味（知乎编辑器会保留一堆无意义的内联样式）。
> 知乎需要**另一套输出**＝干净的语义 HTML（`h2/h3`/`p`/`strong`/`ul`/`blockquote`/`img`）。

## 2. 知乎官方到底开放了什么（能力边界）

`developer.zhihu.com` 于 2026-05 上线，提供 API / MCP / Skill 三种接入方式，
每天 1000 次免费调用额度（我们已在用热榜）。接口全量是**读**能力：

| 能力 | 端点 | 我们现状 | 能拿来做什么 |
|---|---|---|---|
| 热榜 | `GET /api/v1/content/hot_list` | ✅ 已接入（对话页「热点灵感」） | 选题 |
| 知乎搜索 | `/api/v1/content/zhihu_search` | ⚠️ 封装了、UI 未用 | 找相关问题/竞品回答/素材 |
| 全网搜索 | `/api/v1/content/global_search` | ⚠️ 同上 | 事实核查、外部信源 |
| 直答 | `POST /v1/chat/completions` | ❌ | 知乎式问答（simple/deep/deepsearch 三档） |
| **问题推荐** | `question_recommendations` | ❌ | 按账号画像推荐「你可以答的问题」← 很适合做「今天答什么」 |
| **问题回答摘要** | `question_answers` | ❌ | 写之前先看同问题下头部回答写到哪 → 找增量 ← 关键 |
| 内容详情 / 评论 | `user_content_detail` / `_comments` | ❌ | 素材引用 |
| **创作数据** | `creator_account_stats` / `creator_content_stats` | ❌ | **发布后回填**（阅读、赞同、评论等），仅查**自己已发布**内容 |
| 知识库 | `knowledge` 上传/检索 | ❌ | 给 AI 用的资料库，**不是发布** |
| PDF / PPT 生成 | — | ❌ | 周边能力 |

**没有的东西**（这是本次调研的关键结论）：
- 没有任何 create / publish / 草稿箱写入接口；提问也没有。
- 官方 `zhihu-cli` 同样没有发布类命令（唯一写操作是 `auth` 与 `knowledge upload`）。

审计来源：核对了开放平台全部 54 条文档条目，唯一带 POST 语义的 4 个端点都与发布无关
（OAuth token、直答生成、知识库检索、知识库文件上传）——
[「搬运回知乎」的真实可行路径 · API 全量审计](https://github.com/1008611-creater/no.2zhihu/blob/main/docs/publish-path.md)；
另有 [Agentero issue #768](https://github.com/poco-ai/Agentero/issues/768) 独立复核同一结论。

### 「Skill / MCP 能同步内容吗」——不能

官方说的 Skill 与 MCP，是**知乎搜索、热榜、直答这些读能力**的封装形态，
用来接进 Claude / Cursor / Coze / Dify 之类的 Agent 工具链。它解决的仍是
「Agent 怎么读到知乎」，不是「内容怎么发到知乎」。我们已直连 REST，接它没增量。

> 反倒是**我们自己系统的 Skill 体系**（Agent Skills 开放规范，已上线）很适合装一个
> 「知乎内容包」：把「回答体 vs 专栏体 vs 想法」的篇幅、结构、开头钩子、
> 增量自检、话题标签规范写成 `SKILL.md`，写知乎稿时激活。

## 3. 系统现状盘点

**已有的**（加知乎平台的地基都在）：

- `Content.platform` 是 `String(32)` → **加 `zhihu` 不用数据库迁移**；
  `kind` 现有 `text` / `video`，可用来承载 answer / article / pin 三种子形态。
- 平台提示词：`backend/app/prompts/platforms.py` 里 gzh / xiaohongshu / douyin 三套，
  加一条 zhihu 是同一模式。
- 排版引擎已有两条分支：公众号 HTML 排版、小红书纯文本规整（`_layout_xiaohongshu`）。
  知乎是第三条分支，但输出形态不同（见下）。
- 发布队列 + 发布检查 + 检查清单（CHECKLISTS 按平台配置）已成型。
- 非公众号平台已有「复制文案」动作（`onPushDraft` 的 else 分支），可就地升级为
  「复制富文本 + 深链跳转」。
- 知乎热榜已接入（热点灵感卡片），额度纪律（每日 100 次、安全线 88）已建。
- Skill 体系已上线（skills 表 + 内置 skill 上传/启用）。

**缺的**：

1. zhihu 平台提示词与三套子形态模板；
2. 知乎版输出渲染（干净语义 HTML，可粘贴）；
3. 知乎选题入口（问题推荐 / 同问题头部回答）；
4. 队列页的知乎发布动作（复制 + 深链）与检查清单；
5. 发布后 URL 登记 + 数据回填。

## 4. 落地方案（按性价比排序）

### P0 · 新增知乎平台与三种子形态（约 0.5–1 天，收益最大）

- 后端：`PLATFORM_PROMPTS["zhihu"]`，按子形态分三套要求
  - **回答**：结论先行（前两屏给明确答案）→ 分点论证 → 必须写出「比头部回答多了什么」
    → 结尾不做总结套话；600–2000 字
  - **文章**：结构化长文，1500–6000 字，可收进专栏
  - **想法**：50–300 字，单点观点 + 可选话题标签
- 前端：`Platform` 类型加 `zhihu`、ChatView 平台常量、QueueView 平台名与
  `CHECKLISTS.zhihu`（回答必带「问题链接已确认」「已看过头部回答」「增量点是什么」）
- 队列动作：复用现有「复制文案」，升级为「复制富文本」+「去知乎发布」深链
  （回答 → `https://www.zhihu.com/question/{id}`，文章 → `zhuanlan.zhihu.com/write`）

### P1 · 知乎版渲染输出（约 1 天）

Markdown → **干净语义 HTML**（`h2/h3`、`p`、`strong`、`ul/ol`、`blockquote`、`img`、`code`），
一键「复制为可粘贴 HTML」。不要复用公众号内联样式那套。

### P2 · 选题闭环（约 1–2 天，用上两个新接口）

- `question_recommendations`：每日「推荐可答问题」列表
- `question_answers`：动笔前拉同问题头部回答摘要，注入 prompt 作为「已有答案边界」
- 热点灵感卡片加「这条热点 → 知乎相关问题」

### P3 · 效果回填（约 1–2 天）

发布后登记 URL → 定时 `creator_content_stats` 拉阅读/赞同/评论 → 接进内容表现/收益看板。
注意该接口**只查自己账号已发布的内容**，所以必须「人发布 → 回填 URL」这个顺序。

## 5. 红线（不做的事）

1. **不做自动发布**：模拟登录 / 逆向接口 / 浏览器注入填表都违反知乎《用户协议》
   （明令禁止自动化工具访问），有封号风险；且登录态依赖 ZSE-96 等多因子签名、
   有效期短，维护成本极高。
2. **不做批量互动**（自动点赞 / 评论 / 关注）。
3. **不碰盐选与付费内容**（需官方合作资质）。

正确的产品叙事是：**AI 生成 → 人确认 → 人带走 → 人发布**，本系统负责前三步，
第四步由人完成，且「带走」这一步做到极致（一键可粘贴 + 直达编辑器深链）。
