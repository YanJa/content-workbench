# AI 痕迹检测与「加人工痕迹」调研

> 调研时间：2026-10-24
> 需求：① 检测文案有没有人工创作痕迹（AI 味多重）② 给文案添加人工创作痕迹
> 结论先行：**市面上有同类 skill，而且已经很成熟，不用从零造**。但**不能直接照搬**——它们是英文语料出身、面向学术降重，而我们是要发公众号/小红书/知乎的自媒体文案，且「检测」这一半必须重新定义口径。

---

## 1. 市面同类方案盘点

### 1.1 Skill 类（可直接借鉴、甚至直接抄规则表）

| 方案 | 形态 | 覆盖 | 适配度 |
|---|---|---|---|
| **humanizer**（runesleo 版，v2.1.1） | SKILL.md | 9 类 AI 写作模式：浮夸象征、促销腔、-ing 浅析、模糊归因、破折号滥用、三段式、AI 高频词、否定平行、谄媚语气。基于 Wikipedia《Signs of AI writing》 | **本机已装**：`~/.codebuddy/plugins/.../hot-skills/unknown/skills/humanizer/SKILL.md` |
| **humanizer**（blader 版，26 模式 6 组） | SKILL.md + CLI | 增加「聊天残留」（"希望这有帮助"）、格式套路（加粗当装饰）、「为错的读者写」；四步法：标注→改写→审计→定稿；**保留所有事实/数字/引用** | ★54k，社区最火 |
| **humanizer**（acedergren 版） | SKILL.md | 加**分级**（学术 10-20% / 技术 30-50% / 博客营销 70-90% / 社交 100%）+ 密度阈值（AI 词 >3/百词、破折号 >2/段、"However" 开头 >20%） | 阈值的思路值得抄 |
| **humanize-chinese**（swaylq / yukinotech） | 纯 Python 脚本 + JSON 规则 | **中文专用**：规则层（三段式、机械连接词、空洞宏大词、AI 高频词、模板句式、段落均匀度）+ 统计层（困惑度、句长 CV、短句占比、GLTR、逗号密度），阈值按 **HC3-Chinese 对照样本的 Cohen's d 校准** | 中文路线最值得抄 |
| **AI-Text-Anti-Detection-Framework** | prompts + skills | 中英双语，直接操纵 PPL 与 burstiness；宣称 99% → <5% | 对抗性太强，不建议照抄叙事 |

**判断**：规则表可以拿来改（尤其 Wikipedia 那 9 类 + 中文专用的连接词/宏大词表），但两处必须本地化：

1. **换成中文语料**。英文方案的招牌特征是 `delve / tapestry / underscore / it's not just X, it's Y / em dash`，中文里压根不成立；中文真正的特征在**句式与连接词**（见 §2）。
2. **换掉「学术降重」的叙事**。这些工具的场景是「论文过知网/维普」，我们是「发出来的稿子别让人一眼看出是 AI 写的」。前者追求骗过检测器，后者追求**读者读着像人**——这两件事到后期会分岔。

### 1.2 检测产品类（结论：不接）

| 产品 | 准确率（厂商口径） | 独立实测 | API |
|---|---|---|---|
| GPTZero | 99.3% / 误判 0.24% | 真实场景误判 **15-25%**；非母语 **61.22%**（Stanford HAI，TOEFL 作文） | 有，付费 |
| Turnitin | 98% / 误判 <1% | 误判 3.8-15%；**仅机构可用**，个人拿不到 | 无（机构） |
| Originality.ai | 99.1% | 误判 **14.3%**，ESL 偏见 12% | 有，$30/月 |
| 腾讯朱雀 | 95%+ / 误判 <12% | 实测误判 **15-20%**，对学术规范表达过度敏感（人类原创社会学论文被判 38% AIGC 率） | **无开放 API**，免费每日 20 次（单次 5000 字），企业定制才对接 |
| 知网 AIGC | — | 误判 8-12%，无免费额度，报告最细 | 无 |

**不接的三个理由**（这是我的建议，不是中立的罗列）：

1. **没有稳定可用的中文 API**。朱雀是唯一中文强者，但只对公定制；其余都是英文语料出身，对中文的误判只会更高。
2. **把用户未发布的稿件传给第三方**。稿子是用户的资产，发出去之前先过一遍外部服务器，这个默认动作不合适。
3. **给了分数也没法用**。检测器的输出是「疑似概率」，而它自己在人类化文本上只有 11-28% 检出率——**低分不等于人写的，高分也不等于 AI 写的**。拿一个不可靠的分数去指导改写，等于闭眼开车。

## 2. 中文语境下，「AI 味」到底长什么样

英文那套 perplexity / burstiness 直接搬中文会漂（中文没有天然词边界，分词本身引入不确定性；AI 中文的「味道」在句式不在词频）。中文要靠这两层：

### 2.1 规则层（看得见、可指出、能改）

| 类别 | 典型特征 | 举例 |
|---|---|---|
| 机械连接词 | 八股序列、学术腔插入语 | 首先/其次/最后、综上所述、值得注意的是、需要指出的是、总而言之、不难看出 |
| 三段式套路 | 每段都三点、每项都三词 | 「创新、洞察与赋能」「专业、高效、便捷」 |
| 空洞宏大词 | 抽象名词堆叠 | 赋能、抓手、闭环、生态、深耕、赛道、颗粒度、全方位、多维度 |
| AI 高频词 | 直译腔 | 值得一提的是、在这个基础上、进一步、显著、旨在、致力于 |
| 模板句式 | 排比+对仗 | 「不仅……更……」「不是……而是……」高频出现 |
| 结构过整 | 段落长度均匀、每节小标题对仗 | 每段都是 3-4 句 |
| 聊天残留 | 助手语气漏进正文 | 「希望对你有帮助」「以上就是我的分享」「如果你有疑问欢迎」 |
| 太干净 | 零错别字、标点全角统一、无口语、无自我修正 | 人类写作会有「话说回来」「其实我一开始也」 |
| 无具体性 | 只有判断没有证据 | 通篇没有数字、日期、地名、人名、具体事例 |

### 2.2 统计层（看不见、但检测器就在看这个）

HC3-Chinese 对照样本（300 人类 + 300 AI）实测的 Cohen's d，这是**中文最强的几个信号**：

| 指标 | 人类 | AI | Cohen's d |
|---|---|---|---|
| 句长变异系数 CV | 0.52 | 0.32 | **1.22**（最强） |
| 短句占比（<10 字） | 25% | 2.6% | **1.21** |
| 困惑度（字符 3-gram） | ~533 | ~231 | 0.47 |
| GLTR top-10 分桶占比 | 分散 | 集中于高概率字 | 0.44 |
| 逗号密度 | 4.82/百字 | 3.82/百字 | -0.47（**反直觉**：AI 标点更稀） |

**可落地的统计项**（不需要模型、毫秒级）：句长 CV、短句占比、段落长度均匀度、句首重复度、词表丰富度（type-token ratio）、数字/具体名词密度、标点多样性。

## 3. 两个功能该怎么定义（关键：别做错方向）

### 3.1 「检测」不要做成「判定是不是 AI 写的」

这是我最想强调的一点。理由是硬的：

- 真实场景误判率 15-30%，非母语者 61% —— 一个**判定**性结论会冤枉人；
- 我们的稿子 100% 是 AI 参与生成的，**判「是 AI 写的」毫无信息量**，用户早就知道了；
- 用户真正想知道的是：**「发出去会不会被人一眼看出是机器写的 / 会不会被平台或审核盯上」** —— 这是个**特征密度**问题，不是二分类问题。

所以定位应该是 **「人工痕迹体检」**：

```
输入：一段文案 + 目标平台
输出：
  - 人工痕迹指数（0-100，越高越像人写的）  ← 注意方向：别用「AI 率」，越低越好容易看反
  - 命中的特征清单：每条给「是什么 / 在哪（段落号+原文片段）/ 多强 / 怎么改」
  - 平台专属提示：知乎要克制、小红书要口语、公众号要故事感
  - 一句诚实声明：这是特征扫描，不是「是否 AI 生成」的判定
```

方向选择（**人工痕迹分，越高越好**）不是文字游戏：市面工具全是「AI 率，越低越好」，用户很容易看反；我们做的是「补痕迹」，用正向指标更贴合动作目标。

### 3.2 「加人工痕迹」不是同义词替换

humanizer 类工具最大的坑：**改完悄悄把关键数字弄丢了**。所以必须做改写前后事实校验（正则抽出数字/百分比/日期/链接/专有名词，逐一比对，丢了就报警）。

真正有效的三类手段（按效果排序）：

1. **注入不完美**（最像人）：长短句交错、口语插入（"话说回来""其实我一开始也不信"）、自我修正、犹豫标记、适度标点不统一；
2. **加具体性**（最有用）：把「显著提升」换成「从 3 小时压到 40 分钟」；加地名、时间、人名；
3. **打散结构**（最防检测）：拆掉三段式、段落长度拉开、小标题不对仗。

强度要分档（抄 acedergren 的分级思路，按我们的场景定）：

| 档 | 适用 | 做什么 |
|---|---|---|
| 轻度 | 知乎回答、技术文 | 只删机器连接词与套话，不动结构 |
| 中度 | 公众号、知乎文章 | 加主观看法 + 打散结构 + 补具体细节 |
| 重度 | 小红书、生活类 | 全口语化，允许自我修正与半截话 |

### 3.3 平台差异必须进规则

同一段话，在小红书是「人味十足」，在知乎就是「太水」：

| 平台 | 人味的标准 | 反面 |
|---|---|---|
| 公众号 | 有故事、有细节、有情绪起伏 | 干货罗列、要点堆砌 |
| 小红书 | 口语、emoji、碎碎念、亲身经历 | 书面语长句、零口语 |
| 知乎 | 有判断、有边界、承认不确定 | 求互动套话、emoji 堆砌、八股连接词 |
| 抖音 | 短句、强节奏 | 长定语从句 |

## 4. 落到本系统：能不能支持、落在哪

**能，而且基础设施现成**：

| 需要什么 | 现状 |
|---|---|
| 文本处理服务 | `backend/app/services/` 加一个 `humanize.py` 即可（旁证：`zhihu_render.py` 就是这么加的） |
| 改写用的 LLM 通道 | 现成（DeepSeek flash/pro + CF 兜底），`services/llm.py` |
| 内置技能机制 | 现成：`services/builtin_skills/*.md`，不落库、同名用户版优先（v1.6.0 刚为知乎加过） |
| 模型自检工具 | 现成：`tools/builtin.py` 的 `check_compliance`，可加一个 `check_ai_marks` 让模型生成后自己扫 |
| 面板入口 | 现成：加工面板 `LayoutPanel.vue` 工具栏、队列页操作列 |
| 用量统计 | 现成：改写走 LLM 要计费用，`services/usage.py` |

**建议的实现边界**：

- 检测：**零 LLM**（纯规则 + 统计），毫秒级、零成本、可重复、可解释 —— 这也是它和市面付费检测器的核心差异，后者给你一个黑箱概率；
- 改写：**走 LLM**（本地规则改写会把文章改烂，同义词替换只会产生新的机器味），按平台 + 强度档给提示词，走轻量模型即可（flash）；
- 事实校验：**本地硬校验**，改写后比对数字/日期/链接，丢了明确报警，不静默。

**一处诚实约束**（要写进 UI 和 skill，别学市面上的宣称）：我们说「降低被认出是 AI 的特征密度」，**不说「保证通过 XX 检测」**。理由见 §1.2：检测器在人类化文本上的检出率只有 11-28%，任何「包过」的宣称都是骗人。

## 5. 待定的四个决策（需要你拍板）

1. **检测要不要接外部 API**（朱雀/ZeroGPT）→ 我建议**不接**（无稳定中文 API、外传稿件、分数不可靠）；
2. **改写的强度档**是否按平台自动推荐（我建议：默认按平台给档，允许手动改）；
3. **入口放在哪**：加工面板（单篇精修）/ 队列页（批量体检）/ 对话页（生成时自动自检）/ 全都要；
4. **是否做成内置 skill**（像知乎内容包那样，让模型在对话里就能调用）→ 我建议做，成本低收益高。
