# 今日头条与百家号内容生产调研

> 调研目的：在现有「内容运营工作台」中新增**今日头条**、**百度百家号**两个平台的内容生成，并评估「等内容」的扩展路径。
> 调研日期：2026-10-28　｜　适用代码：`content-workbench-pro`（当前版本 1.7.10）
> 说明：平台规则来自公开资料与创作者经验，**字数/阈值属"参考值"，平台会调整，上线后需定期复核**。

---

## 0. TL;DR 结论

1. **架构上零阻力**：现有平台体系就是「`PLATFORM_PROMPTS` 字典 + `PLATFORMS` 白名单 + 子形态表」三件套，`Content.platform` 是 `String(32)` 无枚举约束，**加平台不需要改数据库、不需要迁移**。
2. **两个平台都能复用现成机制**：头条、百家号都是「图文长文 + 短内容」双形态，正好套用知乎 `answer/article/idea` 和公众号 `article/tietu` 已经验证过的**子形态（sub_type）机制**。
3. **MVP 建议先做头条 + 百家号**（推荐/搜索两大主力，规则清晰、可复用），把网易号/搜狐号/大鱼号/企鹅号列为**第二阶段低成本复制**（同一套骨架，只调读者调性与字数）。
4. **工作量约 2–3 人日**（含 prompt 调优与实跑对比），不含富文本精细排版——这两个平台用**纯文本规整**即可，不像公众号需要精细 HTML。

---

## 1. 需求与范围界定

用户原话：「需要再新增今日头条文案文章和百度的百家号等内容生成」。

拆成两件事：

| 项 | 范围 | 优先级 |
|---|---|---|
| **今日头条** | 图文文章（长文）+ 微头条（短内容） | P0 |
| **百度百家号** | 图文文章（SEO 长文）+ 动态（短内容） | P0 |
| **「等」** | 网易号、搜狐号、大鱼号、企鹅号、一点号 | P1（第二阶段） |

> 判断依据：「等」在中文里是"以及同类"，并非明确点名。先把两个点名平台做扎实，第二阶段用同一套机制批量复制更稳。

## 2. 平台规则调研

### 2.1 今日头条（头条号）

**定位**：算法推荐 + 信息流，读者大众化、下沉市场占比高，重「信息增量 + 故事/案例」。冷启动按「旧闻查重 → 一级推荐 → 二级推荐 → 大曝光」推进[^1]。

**图文文章（article）**

| 维度 | 规范 | 来源 |
|---|---|---|
| 标题 | **2–30 字**（建议 15–28），关键词前置；**忌标题党**（夸张/悬念过度会被限流） | [^2][^3] |
| 正文 | 建议 **800–1500 字**（≥300 可发，优质 800+ 更易获推荐） | [^2][^3] |
| 排版 | 每段 **≤3 行**（手机阅读），关键句加粗；「**道理 + 案例**」是基本公式 | [^4][^5] |
| 配图 | 每 **200–400 字**插一张，3–5 张为宜，用平台正版图库防版权 | [^4][^6] |
| 结尾 | 抛一个**具体、有争议空间的问题**；**不要写「点赞关注」**（平台不喜引流） | [^5] |
| 原创/首发 | 勾「原创」（约 3 倍收益）、「首发」（约 2 倍），**须首发于头条** | [^3][^1] |
| 话题 | 2–3 个相关标签 | [^6] |
| 合规 | 无资质不碰医疗/财经/法律/新闻；不导流第三方（微信/QQ/二维码/外链）；不用特殊符号/全英文/繁体标题；旧闻与洗稿查重严 | [^2][^1] |

**微头条（weitoutiao，短内容）**

- 单条**上限 2000 字**，**最佳 300–800 字**；热点短评 100–300、故事 500–600、知识论述接近 800[^7][^8]。
- **没有独立标题**，信息流只露前三行 → **第一行（前 30 字）必须抛冲突/疑问**，不能铺垫[^5]。
- 只讲**一个**观点或一件小事，口语、互动门槛低；适合试错选题 / 涨粉[^5]。
- 生命周期短（1–7 天），热点类约 24 小时[^8]。

### 2.2 百度百家号

**定位**：**百度搜索 + 信息流**，SEO 长尾是核心价值；泛资讯 / 健康 / 财经 / 职场 / 教育。前段判定「领域垂直」，查重严（相似度 >70% 判重）[^9][^10]。

**图文文章（article）**

| 维度 | 规范 | 来源 |
|---|---|---|
| 标题 | **20–30 字**，主关键词**前置**（"前置核心词 + 修饰词"），禁标题党 | [^9][^11] |
| 正文 | **1200–2000 字**（深度 1200–1800 推荐量高）；首段 200 字内出现核心关键词 | [^9][^11] |
| SEO | 关键词密度 **2%–5%**，自然融入不堆砌；用 H2/H3 分节 | [^11][^10] |
| 排版 | 每段 **≤5 行**；数据用项目符号罗列；关键句加粗 | [^9] |
| 配图 | 每 **800 字 ≥2 张**，建议 1200×800，加 ALT | [^9][^12] |
| 原创 | 原创度 **≥85%**（部分口径 90%+），勾「原创声明」 | [^9][^13] |
| 结尾 | 互动引导（如「欢迎评论区交流」） | [^9] |
| 合规 | 不导流（微信/QQ/淘宝）；医疗财经需资质；信用分机制（100 分制，扣分限流） | [^12][^10] |

**动态（dongtai，短内容）**

- 对标微头条：**100–300 字 + 图**，口语化，一个观点；走信息流分发。
- 适合热点点评、观点碎片、轻量互动。

### 2.3 同类平台矩阵（为「等内容」预留）

| 平台 | 依附流量 | 内容偏好 | 复用难度 |
|---|---|---|---|
| **头条号** | 字节信息流 | 资讯/故事/案例，算法推荐 | —（本期） |
| **百家号** | 手机百度/搜索 | SEO 干货、垂直、长文 | —（本期） |
| 网易号 | 网易新闻（跟帖文化） | 易出爆文，审核严，微信同步易不过 | 低（同骨架） |
| 搜狐号 | 搜狐（搜索权重高） | 易入驻、引流限制少 | 低 |
| 大鱼号 | UC/优酷（阿里系） | 补贴多，原创不易 | 低 |
| 企鹅号 | 腾讯新闻/看点 | 审核严、信用分 | 低 |
| 一点号 | 一点资讯 | 需邀请/背书，流量小 | 中 |

> 结论：除一点号外，其余 4 个都是「图文 + 短动态」的同构平台，**第二阶段可直接复用本次的 prompt 骨架**，只替换读者调性与字数区间。

## 4. 落地方案

### 4.1 分期

- **阶段一（P0，本期）**：头条「图文/微头条」+ 百家号「图文/动态」四个形态跑通生成→保存→队列→复制。
- **阶段二（P1）**：网易号/搜狐号/大鱼号/企鹅号，复用骨架批量加。
- **阶段三（P2，可选）**：这两个平台的**富文本排版**（类似公众号），但优先级低——它们后台编辑器粘贴后自带平台样式，纯文本已够用。

### 4.2 Prompt 草案（可直接落 `PLATFORM_PROMPTS`）

**今日头条（平台总纲）**

```text
【平台：今日头条】

目标读者：{audience}
主题：{topic}

先摸清头条的分发逻辑（比格式更重要）：
- 头条靠算法推荐，读者是"被推到你面前"的，不是主动订阅。所以开头 3 行
  必须让人停下滑动：一个具体场景、一个反常识结论、一个真实数字。
- 头条读者大众化，别端着。少术语、多"人话"；道理后面必须跟一个真实案例或场景。
- 标题 2-30 字，关键词前置，忌标题党（夸张/悬念过度会被限流，不做震惊体）。
- 结尾别写"点赞关注"，抛一个具体、有争议空间的问题，让人有话可接。

写作格式要求：用标准 Markdown（# 标题、## 小标题、- 列表、**加粗**），
不要写 HTML 标签。段落短（每段 ≤3 行），每 200-400 字建议配一张图。
```

**头条子形态：图文（article）**

```text
【形态：图文文章】

- 标题 15-28 字，关键词前置，不做标题党
- 正文 800-1500 字，分 3-5 节，每节一个小标题
- "道理 + 案例"：每个观点后面跟一个真实生活场景或具体案例
- 每段 ≤3 行，关键句加粗；每 200-400 字配一张图
- 开头 3 行抓注意力（信息流只露这几行）
- 结尾抛一个具体、有争议空间的问题
```

**头条子形态：微头条（weitoutiao）**

```text
【形态：微头条】

- 没有独立标题，第一行就是钩子：前 30 字必须抛冲突 / 疑问 / 反常识
- 正文 300-800 字（上限 2000），只讲一个观点或一件小事
- 口语、短句，可以带个人语气（"我""今天""刚发现"）
- 段落短，多换行；1-2 个 emoji 可做节奏，不要每行一个
- 结尾一个开放问题，话题标签 2-3 个，`#` 开头空格分隔，单独放最后一行
```

**百家号（平台总纲）**

```text
【平台：百度百家号】

目标读者：{audience}
主题：{topic}

先摸清百家号的分发逻辑（比格式更重要）：
- 百家号吃的是百度搜索 + 信息流，核心资产是 SEO 长尾——标题和首段要
  让人"搜得到、点得进"。
- 标题 20-30 字，主关键词前置（"核心词 + 修饰词"），禁标题党。
- 首段 200 字内必须出现核心关键词；全文关键词自然融入，密度 2%-5%，
  不堆砌。
- 结构用多级小标题（H2/H3）分节，数据用列表罗列，读者能扫读。
- 结尾给一句互动引导（如"欢迎评论区交流"）。

写作格式要求：用标准 Markdown（# 标题、## 小标题、- 列表、**加粗**），
不要写 HTML 标签。每段 ≤5 行。
```

**百家号子形态：图文（article）**

```text
【形态：图文文章】

- 标题 20-30 字，主关键词前置，禁标题党
- 正文 1200-2000 字（深度 1200-1800 推荐量更高）
- 首段 200 字内出现核心关键词；关键词密度 2%-5%，自然融入
- H2/H3 分 3-5 节；数据用项目符号罗列；每段 ≤5 行
- 每 800 字至少 2 张配图
- 结尾一句互动引导
```

**百家号子形态：动态（dongtai）**

```text
【形态：动态】

- 100-300 字，只讲一个观点，口语化
- 第一行有信息量：一个观察 / 反常识判断 / 刚看到的数据
- 段落短，可带 1-2 张配图；结尾一个开放问题
```

### 4.3 子形态机制复用

沿用 `_SUBTYPE_TABLES`：

```python
TOUTIAO_SUBTYPE_PROMPTS = {"article": ..., "weitoutiao": ...}
TOUTIAO_SUBTYPE_LABELS = {"article": "图文", "weitoutiao": "微头条"}
BAIJIAHAO_SUBTYPE_PROMPTS = {"article": ..., "dongtai": ...}
BAIJIAHAO_SUBTYPE_LABELS = {"article": "图文", "dongtai": "动态"}

_SUBTYPE_TABLES = {
    "zhihu": (ZHIHU_SUBTYPE_PROMPTS, "answer"),
    "gzh": (GZH_SUBTYPE_PROMPTS, "article"),
    "toutiao": (TOUTIAO_SUBTYPE_PROMPTS, "article"),
    "baijiahao": (BAIJIAHAO_SUBTYPE_PROMPTS, "article"),
}
```

`normalize_sub_type` / `build_system_prompt` **无需改动**，自动生效。

## 5. 内容策略速查表（可直接转 prompt / 校验规则）

| 形态 | 标题字数 | 正文字数 | 分段 | 配图 | 关键禁忌 |
|---|---|---|---|---|---|
| 头条·图文 | 15–28（≤30） | 800–1500 | ≤3 行/段 | 200–400 字/张 | 标题党、结尾"点赞关注"、导流 |
| 头条·微头条 | 无标题（首行钩子） | 300–800（≤2000） | 短段多换行 | 1–3 张 | 铺垫、朋友圈流水账 |
| 百家号·图文 | 20–30 | 1200–2000 | ≤5 行/段 | 800 字/张 | 关键词堆砌、导流、非垂直 |
| 百家号·动态 | 首行钩子 | 100–300 | 短段 | 1–2 张 | 展开成文章、导流 |

> 通用红线（两平台一致）：无资质不碰医疗/财经/法律/新闻；不导流微信/QQ/淘宝/二维码/外链；原创、首发、查重。

## 6. 合规与风险

1. **平台规则会变**：字数、原创阈值、AI 内容政策都在动态调整。建议 prompt 里的硬数字标注「参考值」，本文档注明复核日期（2026-10-28），每季度校准一次。
2. **AI 生成内容的政策风险**：百家号 2025 年起明确"纯工具生成内容需人工干预，否则不给流量补贴"[^13]。→ 建议这两个平台默认保留 **humanize（去 AI 味）** 环节，或在提示词里强化「个人经验/真实案例」。
3. **无官方发布 API**：头条、百家号都没有公开的发布接口 → 链路仍是「生成 → 人带走 → 人发布 → 回来标记已发」，与小红书/知乎一致，不承诺自动发布。
4. **查重**：两家查重都严（百家号 >70% 判重）。同一篇稿子多平台分发时，**必须做差异化改写**，不能一键原样群发。

## 7. 工作量与优先级建议

| 任务 | 人日 | 说明 |
|---|---|---|
| prompts + 子形态（两端） | 0.5 | 含 4 个形态草案 + 调优 |
| schema + 前端选择器/子形态/队列检查项 | 0.5 | 机械性改动，按清单走 |
| layout 纯文本分支 | 0.3 | 复用 xhs 规整思路 |
| 联调 + 实跑对比（每平台 3–5 篇） | 1.0 | 用真实选题验证字数/语气 |
| **合计（MVP）** | **≈2–3** | 不含富文本精细排版 |

**建议顺序**：头条（读者盘子大、算法推荐）→ 百家号（SEO 长尾、单价高）→ 第二阶段同构平台。
