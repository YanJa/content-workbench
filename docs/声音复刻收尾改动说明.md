# 声音复刻 · 收尾改动说明

本轮是「加上提取声音」需求的收尾，核心功能上一轮已实现并验证，本轮做的是**工程固化**：
让声音复刻这套很挑版本的依赖有章可循、且不拖累主程序安装。

## 一、改了哪些文件

| 文件 | 改动 |
|---|---|
| `backend/requirements.txt` | 新增「声音复刻（可选，默认不装）」注释段，零影响 |
| `backend/app/services/__init__.py` | **由空文件改为**：在包入口装上音频 IO 垫片 |

## 二、requirements.txt 为什么写成注释

最关键的一个决定：**声音复刻的依赖全部以注释形式保留，不作为依赖项生效**。

原因有两条，都是实际会咬人的：

1. **torch 三件套必须从 PyTorch 官方 CPU 源装。** 直接从 PyPI 装默认拉 CUDA 版，多出 2GB+ 体积，而且 `torchvision` 与 `torch` 的 minor 版本必须严格对齐（torch 2.9.x → torchvision 0.24.x），源上的「最新版」会破坏这个关系。
2. **`transformers<5` / `numpy<2.3` 只是 TTS 的需求。** 主程序（对话走 openai SDK、视频渲染走 edge-tts + ffmpeg）根本不需要 transformers，也不依赖 numpy 上限。钉进 requirements 会无谓地卡住主程序将来升级。

现在的状态：`uv pip install -r requirements.txt` 只装 14 条基础依赖，行为和加声音复刻之前**完全一致**；需要复刻时按注释里的两条命令手工装。

## 三、垫片为什么挪到包入口

`app/core/audio_compat.py` 解决的是 torchaudio ≥2.9 委托 torchcodec 导致的 ABI 崩溃（`undefined symbol: torch_list_size`）。此前它只在 `voices.py` 里被导入——只要有人从别的路径先碰到 torchaudio，补丁就来不及装。

现已提到 `app/services/__init__.py` 顶部：只要 `app.services` 下任何子模块被导入，补丁必然先于 TTS 生效，不再依赖具体模块的 import 顺序。`voices.py` 里那句保留，是幂等保险。

| 验证项 | 结果 |
|---|---|
| 后端导入 | `from app.main import app` → `IMPORT OK` |

| 前端类型检查 | `npx vue-tsc --noEmit` 零错误 |
| requirements 解析 | 语法校验通过，14 条有效依赖 |

顺带清掉了一个孤儿文件 `data/voices/profiles/reference.wav`（早期手工测试留下的残留，`list_profiles()` 虽有 `is_dir()` 保护不受影响，但属于磁盘垃圾）。

> 音色验证用的是**分帧自相关取中位数**而非单点估值——单点容易被某个浊音帧带偏，上一轮就因此得出过「参考 106 Hz / 成片 269 Hz」的误导结论。分帧 + 跳过低能量帧 + 取中位数才稳定。
